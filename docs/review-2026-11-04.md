# Semantic Geometry Explorer — code & method review (2026-11-04)

Scope: every file in `backend/app`, `backend/scripts`, `frontend/src`, the gallery
JSON, the docs, and the deployed site (conceptshape.vercel.app + the HF Space
backend). Every claim below marked **measured** was reproduced with the
project's own venv (`backend/.venv`) or against the live deployment on
2026-11-04. The check scripts are not part of the repo; the numbers are
reproducible from the descriptions.

**Verdict.** The product layer (gallery + tour + static fallback) is well
designed and works. The *numbers* under several of the headline demos do not
mean what the tour says they mean, for one shared reason: the BOS token
(`<|endoftext|>`) leaks into every per-layer centering step. The project's own
`tasks/lessons.md` diagnosed exactly this problem for concept pooling and fixed
it there, but the same leak remains in the absolute PCA view, the anchor view,
the cross-model CKA, and the corpus point clouds. Fixing it changes what the
gallery shows, so it is the first thing to decide on. Separately, corpus mode
is broken on the live backend because two dependencies were never added to
`requirements.txt`.

---

## 1. Confirmed problems, ranked by impact

### 1.1 The absolute PCA view is mostly a picture of the BOS token — measured

`Projector._project_pca` centers each layer by the mean over **all** tokens,
BOS included, then fits PCA on the centered stack. BOS has a far larger norm
than any content token at mid layers (Pythia-70M, "I think therefore I am"):

| layer | BOS norm | content median | ratio |
|------:|---------:|---------------:|------:|
| 1 | 16.5 | 7.7 | 2.1× |
| 3 | 123.0 | 12.0 | 10.3× |
| 4 | 121.7 | 11.1 | 10.9× |
| 6 | 116.2 | 81.9 | 1.4× |

Consequences (same sentence):

| | with BOS (current) | BOS excluded |
|---|---:|---:|
| explained variance, 3 PCs | 94.1 % (PC1 alone 87 %) | 61.3 % |
| content-token spread along PC1 at layer 6 (scene units) | 0.008 | 0.624 |
| Spearman(3-D distances, true 512-D distances), layer 2 | **−0.09** | 0.77 |
| … layer 3 | **−0.06** | 0.61 |
| … layer 5 | 0.27 | 0.79 |

So the "94.1 % variance explained" in the sidebar is the BOS outlier, PC1 is
the BOS direction (content tokens are squashed onto a plane), and at layers
2–3 the on-screen distances between words are uncorrelated with their real
distances. The "Hide BOS" toggle hides the sphere but not its effect on the
axes. `steering.json` shows the same thing: PC1 = 89.7 %, BOS at +1.0, every
content token at ≈ −0.5.

Fix: fit the per-layer means and the PCA on content tokens only
(`rs[:, 1:, :]`), then `transform` the BOS rows with the same basis so the
toggle still works. Regenerate the gallery and update the sidebar label.

### 1.2 The cross-model "convergence" demo is a BOS artifact — measured

`/compare` computes CKA on the anchor-descriptor matrices including the BOS
row, with only 6 rows total. Pythia-70M vs GPT-2, "I think therefore I am",
CKA at 7 depth fractions:

| | 0 % | 17 % | 33 % | 50 % | 67 % | 83 % | 100 % |
|---|--:|--:|--:|--:|--:|--:|--:|
| current (BOS row in) — this is what `convergence.json` ships | 0.71 | 0.43 | 0.93 | **1.00** | **1.00** | 0.99 | 0.47 |
| BOS row dropped | 0.74 | 0.11 | 0.28 | 0.24 | 0.27 | 0.13 | 0.26 |
| chance (token rows shuffled, 200 draws) | mean 0.23, 95th pct 0.52 |

The 1.00s the tour presents as model agreement come from one shared outlier
row. Without it the agreement is at chance. This does not mean the Platonic
Representation Hypothesis is false here; it means five tokens and one sentence
cannot measure it. With joint centering (see 1.3) and BOS dropped the curve is
0.76 / 0.88 / 0.96 / 0.79 / 0.80 / 0.55 / 0.73, but with n = 5 that is still
inside the noise band.

Fix: drop the BOS row from CKA/Procrustes; pool tokens from several sentences
(or a paragraph) so n ≥ 30; align by word rather than by position when
tokenizers differ (already noted as a limitation in `alignment.py`); report
the shuffled-token null next to the number. Rewrite the tour step's copy
accordingly.

### 1.3 The anchor view is a 1-D ray, not a 3-D map — measured

`anchor.py` centers tokens *and* anchors by the sentence's token mean. The
anchors (mean-pooled single words from a different context) all sit far from
that mean in the same direction, so a token's four anchor distances are the
same number four times. In `anchors.json` the joint PCA has explained variance
**[0.998, 0.002, 0.001]**, and the correlation between the four anchor-distance
columns across tokens is **1.00**. The "Anchor var. 99.9 %" row in the sidebar
is reporting that collapse as if it were a good fit; Anc-PC2/3 are noise.

`probe.py` already uses the right recipe (center by the mean over probes +
anchors jointly) and gets a healthy [0.58, 0.18, 0.15]. Applying that recipe
to the anchor view gives explained variance [0.86, 0.11, 0.02] and column
correlation 0.14. `compute_anchor_descriptors` and
`compute_anchor_self_descriptors` should share one mean computed over content
tokens + anchors at each layer. (This is also why 1.2 improves.)

### 1.4 Corpus mode is broken on the deployed backend — measured

`requirements.txt` does not list `ripser` or `persim`; `topology.py` imports
them lazily, so the server starts and only the request fails. On the live site,
Corpus → "Philosophy vs Recipe" → Analyze shows:

```
Shape comparison failed: {"detail":"Failed processing 'Descartes': No module named 'ripser'"}
```

Fix: add `ripser>=0.6` and `persim>=0.3` (the Dockerfile already installs
`build-essential` for this) and redeploy the Space. The static gallery example
still works, which is why it was not noticed.

### 1.5 Attention edges never appear at the default layer — measured on the live site

`setTrajectoryData` opens every example at `currentLayer = nLayers` (6).
`AttentionEdges` does `attention.filter(e => e.layer === Math.floor(currentLayer))`,
but attention layers run 0–5. Ticking "Show Attention Edges" on tour step 2
("Turn on attention edges to see…") draws nothing until the user scrubs back.
The attention-sink tour step works only because it hard-codes `currentLayer: 3`.

Fix: residual index *L* is the output of block *L − 1*, so use
`Math.min(Math.max(0, Math.ceil(currentLayer) - 1), nLayers - 1)` (or the
floor variant, documented either way).

### 1.6 Steering direction is taken one block before the injection point — measured

`extract_concept_stream` index *i* is `blocks.{i-1}.hook_resid_post`
(index 0 = embedding). `steer()` builds `pos[layer] - neg[layer]` but injects
at `blocks.{layer}.hook_resid_post`, i.e. index `layer + 1`. Verified:
`residual_stream[3] != blocks.3.hook_resid_post`, `residual_stream[4] ==` it.
At layer 3 the mismatched direction has norm 6.1 vs 7.9 at the matching point.
One-line fix: `pos[layer + 1] - neg[layer + 1]`.

### 1.7 Topology distances are non-deterministic for long texts — measured

`farthest_point_sample` starts from `np.random.randint(N)` with no seed.
Whenever a text exceeds `max_points`, the same text compared with itself gives
a non-zero distance: three runs on one 3000-point cloud subsampled to 400 gave
2.77 / 3.34 / 3.14 — larger than any inter-text distance in the gallery
(0.82–1.75). The milestone's own validation step ("same text twice → ≈ 0")
fails for exactly the long texts the mode was built for.

Fix: seed the RNG, or start FPS from the point farthest from the centroid
(deterministic and arguably better coverage).

### 1.8 `/analyze-batch` mislabels lines after a blank one — measured

Blank lines are skipped during extraction, but results are zipped with
`req.lines[i]` by position. Input `["hello world", "   ", "goodbye moon"]`
returns two results, the second with `text='   '` and the tokens of "goodbye
moon". The LRC parser happens to never send blank lines, so song mode is safe
today; the API is still wrong. Keep the original index alongside each
extraction.

### 1.9 The "wake" budget is shorter than a real cold start — measured

`BackendStatus.wake` polls for 70 s. A cold start of the Space measured
80.8 s to the first `/health` 200. A visitor who clicks "wake (~30s)" sees it
flip back to "asleep" shortly before the backend actually comes up. Raise the
budget to ~150 s and say "~1–2 min".

### 1.10 The probe "reconstruction error" bar does not measure reconstruction

`compute_probe_positions` builds the k-anchor estimate by zero-padding the
dropped columns and pushing the result through the full PCA. A cosine distance
of 0 means "identical to that anchor", so the curve measures the PCA loading
on the zeroed columns, not recoverable information, and the last bar is 0 by
construction (`concept-map.json`: 1.50 / 1.03 / 0.00). The notebook
`anchor_reconstruction_v2.ipynb` ("Fixed") already does this properly with a
Nyström approximation; the app never received that fix. Either port it or drop
the bar; as shipped it supports the scope doc's "geometric extrapolation" claim
without testing it.

## 2. Deployment and robustness

- **Every endpoint is `async def` around blocking PyTorch calls.** That blocks
  the event loop: `/health` cannot answer while any analysis runs, two visitors
  serialize, and a first `/compare` that downloads GPT-2 (~30 s) makes the UI
  report the backend "asleep". Either declare the heavy endpoints as plain
  `def` (FastAPI runs them in a threadpool) and guard the model with a lock, or
  use `run_in_executor`. The shared `_projector.method = req.method` mutation
  and the unlocked `_get_or_load_model` both assume the current serialization.
- **Public limits are sized for local use.** `/text-shape` accepts 500 000
  chars and `max_points` up to 10 000; `milestone-6-corpus-tda.md` itself
  estimates 27 minutes for book-length text and minutes for 10 k-point
  persistence. One request can occupy the free CPU Space for that long. Cap
  via env (e.g. 8 k chars, 3 k points) in production.
- `/text-shape` with `layer` out of range returns a 500 (`index 9 is out of
  bounds`) instead of a 422; validate `-1 ≤ layer ≤ n_layers`.
- The Space currently echoes **any** `Origin` back in
  `access-control-allow-origin` (checked with `https://evil.example`). The
  repo's allowlist would refuse that, so either the deployed code or an HF
  proxy layer differs from the repo. Low risk for a public demo API, but worth
  knowing the allowlist is not what is enforced.
- Chunk windows after the first are run without a BOS token
  (`extract_text_cloud`). Measured effect on a mid-window token is small at the
  final layer (cos 0.999) and modest at layer 3 (0.989); the window's first
  real word becomes the sink (norm 113 vs median 12 at layer 3) but
  center-priority assignment usually discards it. Prepending BOS to every
  chunk is cheap and removes the question.
- The BOS activation is included in every short-text point cloud. In all four
  gallery shapes the BOS point sits at the `[1, 1, ·]` corner of the normalised
  cloud. Dropping that single point moves a text's fingerprint by 0.64
  (Wasserstein combined) against 0.82 between Poetry and Physics, so the
  fingerprints are sensitive to one outlier they should not contain.

## 3. Smaller UX and code notes

- "Spread" and "Hide BOS" controls only render when absolute or compare data
  exists, but anchor, probe, and steer scenes use both.
- `setAnchorData` resets to layer 0; every other mode opens at the final layer
  (the documented lesson).
- Attention edges average all heads. `activeHeads` / `toggleHead` exist in the
  store with no UI; the milestone-2 spec (per-head toggle, per-head colour)
  was dropped and the todo marks M2 complete anyway. The hover tooltip's
  "weight" is a head-average, renormalised over non-BOS tokens when BOS is
  hidden, and does not say so.
- The sidebar "Model" row shows the absolute-mode model while in probe mode;
  `probeConceptsAPI` always sends `pythia-70m` and there is no selector.
- `lrc-parser.ts` rejects `[mm:ss]` tags without a fractional part.
- Dead code: `Projector.fit_basis`, `project_with_basis`, `project_points`
  (`/analyze-batch` re-implements them inline), and
  `extract_concept_embedding` (its comment says BOS is excluded; it is not).
- Pydantic warns at import on every `model_name` field (protected namespace);
  set `model_config = ConfigDict(protected_namespaces=())` once.
- README says "Five things to explore" above a six-row table; every
  "Validation" checklist in `tasks/todo.md` is still unchecked, and 1.2/1.3/1.7
  are the items those checklists would have caught.
- Frontend `tsc --noEmit` is clean; no console errors on the deployed site
  except the 500 from 1.4.

## 4. What is solid

- The precomputed-gallery + tour + static-fallback architecture is the right
  call for a portfolio demo and it works: the site loads instantly, every step
  is interactive without a backend.
- Per-layer centering (the idea) is correct and the lessons file explains why;
  the problem is only which tokens are in the mean.
- `docs/experiments.md` is a model of how to report a failed result.
- The training time-lapse pipeline, the logit lens, the STL export, and the
  notebook v2 Nyström experiment are all sound.

1. Add `ripser` + `persim` to `requirements.txt`, redeploy the Space (minutes;

2. Decide on the BOS/centering changes (1.1, 1.2, 1.3), apply them in

   `/analyze-batch`), `topology`/`extract_text_cloud`, regenerate the gallery
   with `build_gallery.py`, and rewrite the convergence and anchor tour copy

   (1.7), batch index (1.8), wake budget (1.9), layer validation.
4. Threadpool/lock for endpoints and production caps (section 2).
5. Port Nyström reconstruction or remove the bar (1.10).
